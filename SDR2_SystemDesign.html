3.1

Dialogue Pipeline

Core Architecture

The system is built across three networked layers, enabling real-time spoken conversation between a user and a NAO humanoid robot, with responses generated by a cloud-hosted large language model (LLM). The key innovation over a standard scripted robot is that every reply is produced dynamically by Qwen — a state-of-the-art LLM from Alibaba — conditioned on the user's full conversation history, dietary log, and (in Condition B) a live camera image.

Speech Capture & Recognition (PC) The user holds the Space key to speak. pc_voice_proxy.py records audio via PyAudio and calls the Google Speech-to-Text API to obtain a text transcript. Vision keywords (look, see, this) are detected to set needs_vision = true.
2
Command Relay: PC → NAO (TCP :9998) The text and vision flag are sent as a JSON message over TCP to robot_client.py on NAO. A \n delimiter solves the TCP stream boundary problem, enabling reliable message framing without HTTP overhead — critical because NAO runs Python 2.7.
3
Condition-Dependent Image Capture (NAO) Condition B: NAO says "Let me take a look", captures a VGA image via ALVideoDevice, compresses to JPEG (quality 85, ~20–50 KB), and Base64-encodes it for transmission. Condition A: NAO says "I cannot see things around me" — no image is taken.
4
Request Relay: NAO → Server (TCP :9999) robot_client.py opens a short TCP connection to server_brain.py, sending text (and Base64 image if captured) as a single JSON payload. The connection remains open — with a 30-second timeout — to await the LLM response.
5
LLM Query Construction (Server) The server assembles a ChatML message array: a system prompt (personality + nutrition knowledge base + dietary log + vision persona if Condition B), intelligently retrieved conversation history (up to 5 of the 30 most semantically relevant turns), and the current user message — with optional image data.
6
Qwen API Call (HTTPS) The server POSTs to the appropriate Qwen model: qwen-plus (text only) or qwen-vl-plus (with image). The response contains natural-language text plus a self-selected action tag, e.g. [ACTION:nod], chosen by the LLM itself from 22 available gestures.
7
Response Parse & Return The server strips the [ACTION:tag] with a regex, saves the exchange to conversation history, and returns clean text + action tag to NAO over the open TCP socket.
8
Parallel TTS + Gesture Execution (NAO) Two threads launch simultaneously: ALTextToSpeech speaks the response while ALAnimationPlayer performs the corresponding gesture — producing natural synchronised embodied communication.

Key Technical Innovations

🧠
LLM-Powered Dialogue
Every response is generated dynamically by Qwen (Alibaba DashScope), a large language model comparable to GPT-4. Unlike scripted robots, NAO produces contextually appropriate, open-ended answers to any nutrition question. The LLM also self-selects the most fitting body gesture from 22 options.
qwen-plus qwen-vl-plus ChatML format 60-word limit
💾
Persistent Memory System
The server maintains a rolling conversation history (30 turns) per participant IP address. An intelligent retrieval algorithm scores each historical turn by semantic relevance to the current question, injecting the 5 most relevant turns into each LLM call — enabling personalised, context-aware replies throughout the session.
30-turn window keyword scoring top-5 retrieval per-IP isolation
🥗
Personalised Nutrition Q&A
The server automatically detects eating verbs (had, ate, eaten, drank) and meal-time references in user speech, building a live dietary log for the session. This log is injected into every system prompt, so NAO's dinner recommendation genuinely accounts for what the user ate at breakfast and lunch.
food logging meal-time detection diet context injection NUTRITION_KNOWLEDGE

3.2

Non-Verbal Communication Behaviours

Rather than using a fixed rule-based mapping from keywords to gestures, the system delegates action selection to the LLM itself. Each Qwen response is instructed to end with a self-chosen [ACTION:tag]. The server extracts this tag via regex and dispatches the corresponding NAO animation, running in a dedicated thread parallel to speech.

greeting wave nod think explain point thumbsUp celebrate sorry sad confused bow stretch sitDown standUp dance clap shakeHead lookAround airGuitar yoga neutral

Parallel execution: ALAnimationPlayer (gesture) and ALTextToSpeech (speech) run as separate threads, launched simultaneously via Python's threading.Thread. The main thread joins both, ensuring NAO waits for the full response before accepting new input.

3.3

Human Perception & Autonomous Visual Response

Condition B only

The experimental manipulation centres on the robot's ability to perceive its physical environment. The system continuously monitors user speech for vision-trigger keywords. When detected, NAO autonomously captures and analyses a real-time image — the primary difference between conditions.

Aspect Condition A — Control (no_vision) Condition B — Experimental (vision)
Vision trigger Detected but ignored Triggers autonomous image capture
NAO verbal response "I cannot see things around me. Please tell me what you have." "Let me take a look."
Camera action No photo taken VGA 640×480 JPEG captured via ALVideoDevice
Data transmitted to server image_data: null image_data: "<Base64 JPEG, ~20–50 KB>"
LLM model used qwen-plus (text only) qwen-vl-plus (vision-language)
System prompt addition None +VISION_PERSONA: instructs LLM to comment on visible food and appearance naturally
Server safety net Forces image_data = None even if image sent by mistake Image data passed through to vision API

Double-layer condition control: The EXPERIMENT_CONDITION flag is set identically in both robot_client.py and server_brain.py. The robot layer controls physical behaviour (whether to take a photo), and the server layer enforces the same condition independently — preventing any accidental cross-contamination of conditions even if the hardware behaves unexpectedly.
